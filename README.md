# 稿迹 Paper Trail

一个本地优先的论文投稿记录与进度追踪工具。可直接部署到 GitHub Pages，不需要服务器或数据库。

## 功能

- 新增、编辑、删除论文投稿记录
- 记录准备、投稿、编辑处理、外审、返修、接收、拒稿和发表状态
- 状态变更自动进入时间线
- 按标题、期刊、稿号和作者搜索
- 按需要处理、审稿中、已归档筛选
- 导出/导入完整 JSON 备份
- 导出 CSV 表格和 ICS 日历
- 浏览器本地保存和基础离线访问

## 本次升级

- **投稿工作台**：列表 / 看板切换，按待办优先级、最近更新和截止日期排序。
- **下一步建议**：准备中与返修进入待办，审稿阶段独立展示；等待阈值可在「数据与备份」设置。规则在本地运行，不代表期刊审稿周期预测。
- **完整时间线**：修改状态、期刊、轮次或填写本次进展时新增事件；可补录和修改历史节点。当前状态按最后一个事件确定，同日事件按录入顺序排列。普通备注编辑不会重置阶段计时。改投时更新期刊和轮次，历史节点保留原去向。
- **分享进度**：每篇稿件可以生成只读链接；默认匿名，也可选择展示标题和期刊。始终排除作者、稿号、私人备注、投稿系统链接和来信。分享的是已保存记录的静态快照，不会同步后续修改。
- **流程图导出**：在分享窗口一键下载 PNG 图片或 SVG 矢量图。多轮返修按真实事件展开，适合发给合作者或放进汇报。
- **数据保护**：兼容旧版 JSON 数组备份与新版带版本的备份；校验格式后才允许替换。损坏存储不会被自动覆盖，保存失败会提示备份；CSV 防公式执行，ICS 支持中文折行与字符转义。
- **换电脑迁移**：一键导出迁移包；导入时预览新增、重复和冲突，选择合并去重或替换恢复。冲突逐篇选择版本，导入前自动建立一个本机恢复点。

首次打开是空工作台，可点击「先体验示例数据」。示例带有明确标记，可以删除。

### 分享方式

1. 点击稿件上的「分享进度」。
2. 核对预览和匿名选项。
3. 点击「复制分享链接」或下载 PNG / SVG。

分享链接把快照编码在 URL 的 `#share=` 片段中，不需要服务器保存记录，也不是加密。持有链接的人均可读取且无法撤回；分享前请核对内容。超长时间线请发送图片。

本地 `127.0.0.1` 地址不能发给其他设备使用，请发送导出图片，或在 GitHub Pages 部署后生成分享链接。分享页不会导入或修改接收方的本地数据。

## 使用提醒

投稿数据保存在当前浏览器的 `localStorage` 中，不会自动上传到 GitHub。换设备、换浏览器或清理网站数据前，请先导出 JSON 备份。

## 部署到 GitHub Pages

完整材料说明和逐步操作见 [GitHub 部署与迁移指南](docs/DEPLOYMENT.zh-CN.md)。你已有仓库，无需新建。

1. 打开现有仓库 `PKU-AaronYang/paper-trail`。
2. 将源码更新到仓库根目录，默认分支使用 `main`；不要上传迁移包或 `node_modules`。
3. 打开仓库的 **Settings → Pages**。
4. 在 **Build and deployment → Source** 中选择 **GitHub Actions**。
5. 打开仓库的 **Actions** 页面，等待 `Deploy Paper Trail to GitHub Pages` 运行完成。
6. 未配置自定义域名时，预期地址为 `https://pku-aaronyang.github.io/paper-trail/`，最终以 Pages 显示的地址为准。

以后每次向 `main` 分支上传修改，网站都会自动重新部署。

## 本地开发

需要 Node.js 22 和 pnpm：

```bash
pnpm install
pnpm dev
```

生成 GitHub Pages 静态文件：

```bash
pnpm build:pages
```

产物位于 `out/`。

本地预览构建产物：`pnpm preview:pages`。默认开发地址为 `http://127.0.0.1:5173/`，端口被占用时以终端打印的地址为准。

检查：

```bash
pnpm typecheck
pnpm test
pnpm test:smoke
pnpm lint
pnpm build:pages
```

默认启动与构建使用现有 Vite 静态入口，不需要 `.openai/hosting.json`、Cloudflare 数据库或账户。依赖版本与原锁文件保持一致。

### 换电脑操作

1. 旧电脑：「数据与备份」→「导出迁移包」，将 JSON 文件传到新电脑。
2. 新电脑：打开网站 →「数据与备份」→「导入迁移包 / JSON」。
3. 查看预览。默认「合并去重」保留本机记录，按内部 ID 去重；冲突时逐篇选择完整版本。不同 ID 的同名论文不会自动合并。
4. 如果要完全恢复旧电脑内容，选择「替换恢复」并勾选确认；空文件替换会清空记录。
5. 误操作时，可从「恢复上次导入前的数据」打开恢复点，再选择「替换恢复」。每次导入只保留上一次导入前的数据；它仍在同一浏览器，不能替代外部备份。

迁移包含全部论文、私人字段与历史，不包含等待提醒设置。它是手动迁移，不是实时同步；旧版 JSON 备份也可使用同一入口导入。

### 使用边界

- 数据按浏览器和网站地址隔离；本地预览、GitHub Pages、不同浏览器不会自动同步，使用 JSON 备份迁移。
- 截止提醒只在打开页面时展示；没有后台推送。ICS 可导入你使用的日历。
- 离线支持缓存成功访问过的页面资源，首次使用需要联网打开网站。
- 目前不登录期刊网站、不自动抓取投稿状态，也不调用外部 AI。已移除编辑来信提取入口，进展由用户手动维护。

后续可以在这套本地工作流上继续增加审稿意见清单、可选模型辅助解析、跨设备同步；这些功能尚未实现。
