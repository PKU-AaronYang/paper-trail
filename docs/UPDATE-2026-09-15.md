# 2026-09-15 稿迹更新指南

## 更新后原记录会保留吗？

会继续读取原记录。本版仍使用 `paper-trail:data:v1` 保存数据，旧版没有关键词的记录也能正常加载。不需要为了更新网站重新导入数据。

条件是：继续使用原来的 HTTPS 网站地址、原浏览器和同一浏览器配置，没有清除网站数据。无痕模式、换浏览器、换电脑或改域名不具备这一条件。网站源码和浏览器个人数据分别存储；上传源码本身不会上传、清空你的论文。

更新前先导出迁移包是额外保障。不要删除仓库，不要清除网站存储，不要上传个人 JSON。若看到旧界面，先 Ctrl+F5 强制刷新，而不是清除网站数据。

技术依据：[MDN localStorage 说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)。

## 本版包含什么

1. 文案改为「投稿总览」「投稿工作台」「从第一稿，到正式发表」。
2. 「需要处理」只包含准备中和返修。「已归档」包括接收、发表、拒稿和撤稿。所有归档仍可打开编辑。
3. 移除编辑来信提取入口。
4. 每个已保存节点的编辑区域增加删除按钮，删除需确认。删除最新节点会按剩余最新事件回退状态；全部删除时保留稿件当前状态。
5. 每篇论文可设置关键词，支持中文/英文逗号、分号分隔，在列表和看板展示，也能搜索。迁移包与 CSV 保留关键词，分享快照不包含关键词。
6. 顶部新增「使用说明」按钮。
7. 「数据与备份」首行并列显示「导出迁移包」「导入迁移包」。导入先预览，选择合并或替换，冲突逐篇选择，并保存导入前恢复点。

## 最简单的更新方式：只上传本次更新包

使用 `paper-trail-update-2026-09-15.zip`，不是旧版源码 ZIP。

1. 在当前线上稿迹打开「数据与备份」→「导出迁移包」，把个人 JSON 保存到电脑其他文件夹。
2. 解压本次更新 ZIP。里面有 `app`、`components`、`lib`、`public`、`scripts`、`tests`、`docs` 文件夹以及 `README.md`。
3. 打开 `https://github.com/PKU-AaronYang/paper-trail`，确认在 `main` 分支。
4. 点击 **Add file → Upload files**。把解压目录里面的文件和文件夹一起拖入。不要把外层文件夹或 ZIP 本身拖进去，也不要把子文件全部平铺到根目录。
5. 提交前检查上传路径应为 `app/page.tsx`、`components/usage-guide.tsx` 等，而不是 `paper-trail-update/app/page.tsx` 或根目录 `page.tsx`。
6. 填写提交说明 `Update archive, keywords, timeline and migration`，点击 **Commit changes**，提交到 `main`。如仓库要求 Pull Request，按提示合并到 `main`。
7. 在 **Actions** 等待 **Deploy Paper Trail to GitHub Pages** 绿色成功。未自动运行时，进入此工作流 → **Run workflow → main**。
8. 打开原网站，Ctrl+F5 刷新。确认顶部有「使用说明」、统计卡有「已归档」，以及数据与备份首行有「导入迁移包」。
9. 检查原论文数量和一篇时间线即可，正常显示时无需导入备份。

本次没有修改部署工作流和依赖文件，不需要重复上传 `.github`，不会再遇到隐藏目录上传问题。也不需要重设 Pages、删除旧仓库或上传 `out` 目录。

## 导入迁移包在哪？

右上角「数据与备份」→ 顶部「迁移到新电脑」→「导入迁移包」。选择旧电脑导出的 JSON，先预览，再选择合并或替换。迁移文件与分享链接、PNG 图片是不同的材料。

若仍看不到这个按钮，先核对 Actions 是否部署成功以及是否打开了原网站的最新版本，不要因此清除浏览器数据。
